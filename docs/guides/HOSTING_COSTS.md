## 1. Что значит «1000–2000 человек» по нагрузке

1000–2000 зарегистрированных ≠ 1000–2000 одновременных запросов. Реальная картина для такого сервиса:

| Показатель | Оценка |
|---|---|
| Всего пользователей | 1000–2000 |
| Активных в день (DAU) | ~100–300 |
| Одновременных в пик | **30–60** |
| Проверок в месяц | ~3000–5000 |
| Тяжёлых операций (парсинг/VIN/ИИ) на проверку | 1–3 |

Вывод: это **умеренная нагрузка**. Сайт «ляжет» не от количества пользователей, а от **двух конкретных вещей**: (1) синхронных тяжёлых операций, которые блокируют веб-процесс, и (2) SQLite, который не держит конкурентную запись. Решив эти две вещи, ты спокойно держишь такую аудиторию на недорогом хостинге.

## 2. Архитектура «чтобы не лёг» (что и почему)

### Узкое место №1: тяжёлые операции в веб-процессе
Парсинг объявления, VIN-запрос и ИИ-анализ занимают секунды. Если они выполняются прямо в обработчике HTTP-запроса, каждый такой запрос держит воркер занятым — при 30 одновременных проверках веб «встаёт».

**Решение (код уже есть):** Redis-очередь + отдельный воркер (`app/workers/worker.py`, `TASK_QUEUE_ENABLED=true`). Веб мгновенно возвращает «задача в работе», воркер делает тяжёлое в фоне, фронт опрашивает статус. Воркеры масштабируются независимо от веба.

### Узкое место №2: SQLite
SQLite не рассчитан на параллельную запись — при нескольких одновременных проверках начнутся блокировки БД.

**Решение:** **PostgreSQL** (Railway Postgres или Supabase) + пул соединений через asyncpg. Уже поддержано в коде (`DATABASE_URL=postgresql+asyncpg://…`).

### Узкое место №3: парсинг Avito (капча + память)
Свой Chromium (Playwright) ест ~300–500 МБ памяти на инстанс и ловит капчу на новом IP.

**Решение:** **ScrapingBee** (скрейпинг-API) — он сам обходит антибот и рендерит страницу, тебе приходит готовый HTML. Память на браузер не тратится, контейнер становится лёгким. Логика разбора (BeautifulSoup) остаётся.

### Защита от лишней нагрузки и трат
- **Кэш в Redis**: результат парсинга объявления и VIN кэшировать — повторный запрос того же не дёргает внешний сайт и не тратит деньги.
- **Rate limiting в Redis** (`RATE_LIMIT_STORAGE=redis`): защита от ботов и абуза, работает при нескольких инстансах API.
- **Горизонтальное масштабирование**: т.к. сессии и rate limit в Redis, можно поднять 2–3 реплики API за балансировщиком Railway без проблем.

### Итоговая схема
```
                    ┌──────────────┐
   Пользователь ──► │  Vercel CDN  │  (фронт Vue SPA, статика, бесплатно/дёшево)
                    └──────┬───────┘
                           │ /api
                    ┌──────▼───────┐      ┌──────────────┐
                    │  API (FastAPI)│◄────►│ PostgreSQL   │
                    │  2–3 реплики  │      │ (Railway/Supabase)
                    └──────┬───────┘      └──────────────┘
                           │ ставит задачи
                    ┌──────▼───────┐      ┌──────────────┐
                    │   Redis      │◄────►│  Worker(ы)   │──► ScrapingBee / Autocode / OpenRouter
                    │ очередь+кэш  │      │ (парсинг,VIN,│
                    └──────────────┘      │  ИИ, PDF)    │
                                          └──────────────┘
```

| Статья | Что это | $/мес | ₽/мес (≈95₽/$) |
|---|---|---|---|
| **Railway** | API + воркеры + Postgres + Redis | 35–50 | 3 300–4 750 |
| **ScrapingBee** | Скрейпинг Avito (~6000 парсингов, тариф Freelance) | 49 | 4 650 |
| **OpenRouter** | ИИ (GPT-4o-mini, vision, Whisper) | 5–15 | 475–1 425 |
| **Resend** | Транзакционная почта (free tier хватает на старте) | 0 | 0 |

| **Sentry** | Мониторинг ошибок (free tier на старте) | 0 | 0 |
| **PostHog** | Аналитика (free tier до ~1M событий/мес) | 0 | 0 |
| **Домен** | .ru/.com (в год, ~раскидать на месяц) | ~1 | ~100 |
| **ИТОГО** | | **~$90–135** | **~8 500–12 800 ₽/мес** |

На 1000–2000 пользователей этих ресурсов достаточно с запасом. ИИ почти бесплатен (GPT-4o-mini дешёвый). Главные статьи — Railway и ScrapingBee.

### Если хочется дешевле (VPS-вариант)
Вместо Railway можно взять один VPS (например, 4 ГБ RAM, 2 vCPU за ~600–1200₽/мес у российского/европейского провайдера) и поднять всё через `docker-compose.vps.yml` + Caddy (HTTPS) — конфиги уже есть. Минус: всё на одной машине, сам отвечаешь за бэкапы и масштабирование. Для старта на 1–2k — рабочий бюджетный вариант. Railway проще и масштабируется в один клик.

## 4. Переменные расходы: Autocode (VIN) — главная статья риска

Это **не инфраструктура**, а себестоимость, которая перекладывается на пользователя через цену отчёта.

- Полный VIN-отчёт Автокода: **~60₽/шт** (уточнить под договор).
- Базовый VIN-отчёт: **~3₽/шт**.
- Себестоимость базовой проверки **без полного VIN**: ~3₽ (скрейпинг ~0,8₽ + ИИ ~2₽).

**Куда класть деньги за VIN:** на **баланс B2B-аккаунта Автокода** (предоплата, отчёты списываются с него). Начни с суммы на 10–20 отчётов для теста.

**Правило, чтобы не уйти в минус:** полный отчёт НЕ в безлимите Pro. В коде уже стоит квота 10 базовых VIN/мес на Pro + платные пакеты сверх (5/490₽, 10/890₽, 20/1590₽). Если реальная цена отчёта выше ~60₽ — уменьши `PRO_VIN_REPORTS_INCLUDED`.

## 6. Точка безубыточности

Подписка Pro 990₽/мес после комиссии ЮKassa ≈ 955₽. При базовой модели (VIN метрический, полный отчёт платный сверх квоты) вклад одного Pro-подписчика ≈ 900₽/мес.

Инфраструктура ~10 500₽/мес окупается с **~11–12 подписчиков**. С запасом на поддержку — **ориентир 15–20 платящих = выход в плюс**. Каждый проданный пакет VIN-отчётов (например, 890₽ за 10 при себестоимости ~600₽) добавляет маржу сверху.
