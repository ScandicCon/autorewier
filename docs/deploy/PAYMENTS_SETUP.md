# Полный гайд: приём платежей Pro через ЮKassa

> Пошаговая инструкция, как включить приём денег за подписку Pro на боевом сайте.
> Код приёма платежей уже написан и проверен — нужно вписать ключи, настроить вебхук и протестировать.
> Бэкенд: Railway (`autorewier-production.up.railway.app`). Фронт: Vercel (`autorewier.vercel.app`).

---

## Как это работает (общая схема)

```
Пользователь → кнопка «Перейти на Pro» в кабинете
   → бэкенд создаёт платёж в ЮKassa (POST /api/v1/payments/subscribe)
   → пользователя редиректит на страницу оплаты ЮKassa
   → пользователь платит
   → ЮKassa шлёт уведомление (webhook) на бэкенд
   → бэкенд проверяет платёж и активирует Pro на 30 дней
   → пользователя возвращает на сайт (YOOKASSA_RETURN_URL)
```

Тебе нужно соединить три вещи: **ключи ЮKassa**, **вебхук** и **переменные на Railway**. Ниже — по шагам.

---

## Что уже готово в коде (ничего делать не надо)

- Создание платежа с идемпотентным ключом и суммой подписки.
- Вебхук с тройной защитой: allowlist IP ЮKassa (диапазоны уже зашиты в дефолт), идемпотентность (повторное уведомление не активирует Pro дважды), сверка статуса и суммы напрямую через API ЮKassa.
- Активация Pro на 30 дней, продление складывается.
- Тарифы: Pro = **990 ₽/мес**, Free = **3 проверки/мес** (сброс по месяцам).
- Кнопка оплаты в кабинете подключена к запуску платежа (исправлено в ходе аудита — раньше была неактивна).

---

## Предусловия

1. У тебя есть аккаунт **ЮKassa** и **магазин прошёл модерацию** (статус «Активен»). Без активного магазина боевые платежи приниматься не будут.
2. Заключён договор, указаны реквизиты для выплат.
3. Доступ к панели Railway (сервис `autorewier`) и к git-репозиторию (для деплоя кнопки).

---

## Шаг 1. Получить ключи в кабинете ЮKassa

Зайди в личный кабинет ЮKassa (yookassa.ru):

1. **shopId (идентификатор магазина):**
   - Раздел **Настройки → Магазин** (вверху страницы рядом с названием магазина также часто виден shopId).
   - Это число вида `123456`. Запиши.

2. **Секретный ключ:**
   - Раздел **Интеграция → Ключи API**.
   - Нажми **«Выпустить ключ»** (для боевого приёма — рабочий ключ, начинается с `live_…`; для теста — `test_…`).
   - Ключ показывается **один раз** — сразу скопируй и сохрани в надёжном месте.

> Боевой ключ (`live_…`) принимает реальные деньги. Тестовый (`test_…`) — для проверки без списаний. Для финального запуска нужен боевой; для первого прогона удобно сначала проверить тестовым.

---

## Шаг 2. Настроить вебхук (HTTP-уведомления) в ЮKassa

1. Раздел **Интеграция → HTTP-уведомления**.
2. В поле URL вставь:
   ```
   https://autorewier-production.up.railway.app/api/v1/payments/webhook/yookassa
   ```
3. Включи событие **`payment.succeeded`** (можно включить все события — лишние бэкенд просто проигнорирует, но `payment.succeeded` обязателен).
4. Сохрани.

Это адрес, на который ЮKassa сообщит «платёж прошёл», и бэкенд активирует подписку.

---

## Шаг 3. Вписать переменные на Railway

Открой Railway → проект → сервис **autorewier** → вкладка **Variables**. Добавь/проверь:

| Переменная | Значение | Примечание |
|---|---|---|
| `YOOKASSA_SHOP_ID` | твой shopId (например `123456`) | из Шага 1 |
| `YOOKASSA_SECRET_KEY` | твой ключ (`live_…` или `test_…`) | из Шага 1 |
| `YOOKASSA_RETURN_URL` | `https://autorewier.vercel.app/app` | куда вернуть пользователя после оплаты |
| `ALLOW_DEV_PAYMENT_BYPASS` | `false` | или не задавать — в проде и так выключено |

**Менять НЕ нужно:** `YOOKASSA_WEBHOOK_ALLOWLIST` — в дефолте уже прописаны официальные IP-диапазоны ЮKassa.

После сохранения переменных **дождись нового деплоя** (вкладка Deployments → свежий зелёный деплой). Без передеплоя новые ключи не применятся.

---

## Шаг 4. Выкатить кнопку оплаты на фронт

Фикс кнопки уже в коде, его нужно закоммитить и запушить (Vercel пересоберётся):

```powershell
git add frontend/src/api/inspectionApi.js frontend/src/views/DashboardView.vue
git commit -m "feat: кнопка оплаты Pro запускает платёж ЮKassa"
git push
```

---

## Шаг 5. Проверить оплату в бою (smoke-тест)

1. Зайди на `https://autorewier.vercel.app` → войди в аккаунт.
2. Кабинет → вкладка **«Подписка»** → кнопка **«Перейти на Pro»**.
3. Должно перебросить на страницу оплаты ЮKassa.
   - Если используешь **тестовый** ключ — оплати тестовой картой `5555 5555 5555 4444`, срок — любой будущий, CVC — любой.
4. После оплаты тебя вернёт на сайт (`/app`).
5. Проверь, что подписка стала **Pro** и лимит бесплатных проверок снят.

Если всё прошло — переключай на боевой ключ (`live_…`) и делай реальный платёж на 990 ₽ для финальной проверки.

## Если что-то не работает (диагностика)

| Симптом | Причина и решение |
|---|---|
| Кнопка выдаёт «Оплата временно недоступна» (503) | `YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET_KEY` не заданы или сервис не передеплоился. Проверь переменные и дождись деплоя. |
| Редиректит на оплату, но после оплаты Pro не включается | Не приходит вебхук. Проверь в ЮKassa (Интеграция → HTTP-уведомления), что URL верный и событие `payment.succeeded` включено. В Railway → Logs посмотри, приходит ли запрос на `/payments/webhook/yookassa`. |
| Вебхук приходит, но отклоняется (403) | IP отправителя не в allowlist. Обычно дефолт покрывает все IP ЮKassa; если они добавили новые — допиши их в `YOOKASSA_WEBHOOK_ALLOWLIST`. |
| После оплаты не возвращает на сайт | `YOOKASSA_RETURN_URL` не задан или ведёт на localhost. Поставь `https://autorewier.vercel.app/app`. |
| Ошибка при создании платежа (502) | Неверный ключ или магазин не активен. Проверь ключ и статус магазина в ЮKassa. |

## ⚠️ Юридическое: фискализация (54-ФЗ) и НДС

При продаже подписки физлицам в РФ по **54-ФЗ** обычно требуется **фискальный чек**. ЮKassa умеет формировать чеки (своя онлайн-касса или интеграция), но это включается отдельно, и в текущий запрос на создание платежа данные чека (`receipt`) пока не передаются. Перед массовым приёмом денег уточни у ЮKassa, нужна ли тебе фискализация под твою схему, и при необходимости добавь передачу `receipt`. Учти также **изменение ставок НДС с января 2026** — если используешь чеки, ставка должна быть актуальной.

## ⚠️ Для прибыли: метрирование Autocode (сделать ДО реальных ключей Autocode)

Сейчас на Pro — **безлимит проверок**, и каждая проверка с VIN тянет Autocode-отчёт. Пока Autocode в демо-режиме это бесплатно. Но с реальными ключами:

- полный отчёт ~**60 ₽**; при безлимите активный перекуп выводит в минус (~16 полных отчётов = вся подписка 990 ₽);
- защиты по стоимости сейчас нет (только rate-limit от абуза).

Рекомендация (см. `guides/LAUNCH_AND_PROFIT_PLAN.md`): не включать полный отчёт в безлимит — либо базовый отчёт (~3 ₽) по умолчанию + полный как платная опция, либо месячная квота VIN на Pro. Небольшая доработка кода; сделать до подключения Autocode.
