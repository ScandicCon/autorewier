РИСКИ & MITIGATION
─────────────────────────────────────────────────────────────────────────────

Top 3 Critical Risks:

1. Parser Rate Limiting / Blocking
   Probability: HIGH (80%)  Impact: HIGH (60%)
   Mitigation: Exponential backoff, proxy rotation, captcha detection
   Contingency: Selenium + headless browser OR manual URL input
   → Full strategy in RISK_REGISTER.md

2. Database Migration Failure
   Probability: MEDIUM (30%)  Impact: CRITICAL (100%)
   Mitigation: Test locally, rollback script, backup before deploy
   Contingency: pg_restore from backup
   → Full strategy in RISK_REGISTER.md

3. LLM API Costs > Budget
   Probability: MEDIUM (40%)  Impact: HIGH (30%)
   Mitigation: Token counting, response caching, rule-based fallback
   Contingency: Disable LLM for free tier, cheaper model
   → Full strategy in RISK_REGISTER.md

All 12 risks documented in RISK_REGISTER.md with escalation procedures.

ESCALATION PROCEDURES
─────────────────────────────────────────────────────────────────────────────

Level 1: Minor Issue (1 person affected)
  → Slack thread in #sprint-podkapot
  → Owner: responsible dev
  → SLA: Same day fix

Level 2: Blocker (2+ people affected)
  → Slack mention + 15min sync
  → Owner: team lead
  → SLA: 2 hours fix

Level 3: Critical (project at risk)
  → Emergency all-hands
  → Decision: PM + tech lead
  → SLA: 30 min decision

Example: "Parser success <80% for 2 hours"
  → Escalate to backend lead + PM
  → Emergency decision needed within 30 min
  → Possible outcomes:
     A) Additional retry strategy
     B) Switch to Selenium/headless browser
     C) Enable manual URL input fallback
     D) Defer Avito integration to v1.1

→ Full escalation matrix in RISK_REGISTER.md
