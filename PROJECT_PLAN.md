# AutoRewier / ПОДКАПОТ — План проекта

> Полный разбор проекта «по полочкам»: идея, что сделано, что нужно доделать для полноценной работы сайта, и идеи для улучшений.
> Составлено: 11 июня 2026.

---

## 1. Идея проекта

**AutoRewier** (бренд лендинга — **«ПОДКАПОТ»**) — это B2C-сервис на Python для **проверки б/у автомобиля перед покупкой или перепродажей** (рынок РФ).

Пользователь даёт:
- ссылку на объявление (Avito / Auto.ru / Drom),
- VIN,
- замеченные дефекты и свои предпочтения.

Сервис в ответ:
- парсит объявление и достаёт данные авто,
- оценивает **риски** и нормы пробега,
- считает **стоимость ремонта и запчастей** (Avito со ссылками + Exist/Emex как ориентир без ссылок),
- проверяет **VIN через Autocode** (история, ограничения),
- выдаёт **вердикт**: «стоит смотреть» / «с осторожностью» / «не стоит»,
- формирует **чеклист осмотра** и **PDF-отчёт**,
- поддерживает **режим перекупщика** (экономика перепродажи),
- умеет **мониторить объявление** (изменение цены/статуса).

Два интерфейса поверх одной бизнес-логики: **веб-кабинет** (Jinja + Vue SPA) и **Telegram-бот**. Монетизация — подписка **Pro** через **ЮKassa**.

## 2. Технологический стек

| Слой | Технологии |
|------|-----------|
| Backend | FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic v2 |
| БД | PostgreSQL / Supabase (прод), SQLite (dev) |
| Frontend | Vue 3 + Vite (SPA в `frontend/`), плюс legacy Jinja-страницы |
| Бот | aiogram 3 |
| Парсинг | Playwright + Chromium, httpx, BeautifulSoup/lxml |
| LLM | OpenRouter (GPT-4o-mini), Whisper для голоса, vision для фото |
| Платежи | ЮKassa |
| Почта | Resend (заменил заблокированный SMTP) |
| Инфра | Docker Compose, Caddy (HTTPS), Redis-воркер, Prometheus-метрики |
| Деплой | Railway (backend) + Vercel (frontend), либо VPS |

## 3. Что уже сделано ✅

### Backend / бизнес-логика (зрелая, ~4300 строк сервисов)
- **Ядро анализа** (`services/analysis.py`, 1091 строка): риски, нормы пробега РФ, расчёт ремонта, экономика перепродажи, вердикт.
- **Парсеры** Avito / Drom / Auto.ru на Playwright с обработкой капчи, кэшем, ретраями, прокси и профилем браузера.
- **Цены на запчасти** (`parts_prices.py`): Avito со ссылками + магазины как ценовой ориентир; объединение в `estimate_min/max`.
- **Autocode** (VIN): интеграция с B2B-API + демо/mock-режим без ключей.
- **Подписка Pro** через ЮKassa: вебхук с проверкой IP по allowlist, идемпотентностью, сверкой статуса платежа, dev-обходом.
- **LLM-обогащение**: текст анализа, **анализ фото** (vision) с keyword-fallback, **транскрипция голоса** (Whisper), генерация текста объявления, **помощник в торге** (`negotiation`), **сравнение с рынком** (`market_comparison`).
- **Мониторинг объявлений**: фоновый цикл (`run_monitoring_cycle`) + Redis-воркер-планировщик, отслеживание изменений цены/статуса.
- **PDF-отчёты** (reportlab), **чеклист осмотра**.

### API
- REST-эндпоинты: auth, inspections (CRUD + post-inspection пересчёт), сравнение осмотров, VIN-проверка (sync + async через задачи), PDF, мониторинг объявлений, платежи, админ (`/health`, `/stats`), support.
- Три способа авторизации: cookie-сессия, JWT Bearer, Telegram-заголовки.

### Frontend
- **Vue 3 SPA**: Landing, Login, Register, VerifyEmail, Dashboard, NewInspection, InspectionDetail; guard на авторизацию; готовая прод-сборка в `frontend/dist`.
- Legacy Jinja-кабинет (`/cabinet/*`) — работает параллельно.
- Набор HTML-концептов дизайна и pixel-арт макеты (`podkapot/`, `concept-*.html`).

### Telegram-бот
- Полный сценарий новой проверки (URL → предпочтения → марка/модель/год/пробег/цена → дефекты → режим перекупщика → целевая цена), чеклист, пост-осмотр, помощь/отмена.

### Инфраструктура и качество
- Конфиг через pydantic-settings (~80 параметров), валидация production-настроек.
- Rate limiting, JSON-логи, Prometheus `/metrics`, админ-API по токену.
- Docker Compose (base + VPS-оверлей с Caddy/HTTPS), Dockerfile, конфиги Railway/Vercel.
- Alembic-миграции (идемпотентные, под Supabase pooler/asyncpg).
- **153 теста** (pytest): e2e критические потоки, парсеры, платежи, капча, PDF, вердикт, email-верификация и др.
- Обширная проектная документация (SPRINT_*, QA_*, RISK_REGISTER, ARCHITECTURE_DECISIONS и т.д.).

## 4. Что нужно доделать для полноценной работы 🔧

### 4.1 Критично (без этого сайт не «живой»)
- [ ] **Зелёный тест-сьют.** Кэш `pytest` показывает падавшие модули: `test_negotiation`, `test_image_analysis_llm`, `test_market_comparison`, `test_pdf_report`, `test_password_confirm`, `test_api_regression`, один webhook-тест. Прогнать `pytest`, починить красные, зафиксировать как CI-гейт.
- [ ] **Боевые ключи и секреты.** `.env` для прод: `WEB_SECRET_KEY` (64 симв.), `OPENROUTER_API_KEY`, `YOOKASSA_SHOP_ID/SECRET_KEY`, `RESEND_API_KEY`/SMTP, `AUTOCODE_*`. Сейчас без них половина фич уходит в демо/выключена.
- [ ] **Проверить реальный деплой end-to-end.** Railway (backend+Postgres) ↔ Vercel (frontend) ↔ домен: миграции при старте, CORS (`CORS_EXTRA_ORIGINS` с Vercel-доменом), cookie `SameSite=none; Secure`, `WEB_BASE_URL`.
- [ ] **Подтвердить работу платежей в бою.** Реальный платёж ЮKassa → вебхук → активация Pro; проверить allowlist IP и `YOOKASSA_RETURN_URL` на проде; выключить `ALLOW_DEV_PAYMENT_BYPASS`.
- [ ] **Email-верификация на проде.** Resend-домен подтверждён (DKIM/SPF), письма доходят, `REQUIRE_EMAIL_VERIFICATION=true` отрабатывает корректно.

### 4.2 Важно (стабильность ключевых фич)
- [ ] **Устойчивость парсинга Avito.** Капча на новом IP — главный риск. Настроить резидентный прокси, профиль браузера, мониторинг доли успешных парсингов; продумать graceful-деградацию (ручной ввод данных, если парсер упал).
- [ ] **Autocode B2B-доступ.** Получить реальный аккаунт, проверить списание баланса, обработать ошибки/пустые отчёты; решить, кто платит за запросы (лимиты на пользователя).
- [ ] **Мониторинг объявлений в проде.** Сейчас планировщик живёт в Redis-воркере (`TASK_QUEUE_ENABLED=true`). Поднять воркер как отдельный процесс/сервис на Railway, проверить интервал и доставку уведомлений пользователю (бот/почта).
- [ ] **Доставка уведомлений.** Связать события мониторинга и пост-осмотра с каналами (Telegram-пуш / email) — проверить, что `verification_delivery` и уведомления реально уходят.
- [ ] **Единый фронтенд.** Решить судьбу двух UI: Vue SPA vs legacy Jinja-кабинет. Дублирование путает и удваивает поддержку — выбрать SPA как основной, Jinja оставить только для лендинга или убрать.

### 4.3 Желательно (перед публичным запуском)
- [ ] Юридическое: оферта, политика конфиденциальности, согласие на обработку ПДн (152-ФЗ), дисклеймер «цены ориентировочные, не оферта».
- [ ] Обработка ошибок и пустых состояний в UI (парсер упал, VIN не найден, LLM недоступен).
- [ ] Лимиты бесплатного тарифа (`free_inspections_per_month=3`) — проверить корректность счётчика и сброса по месяцам.
- [ ] Логи ошибок в внешний сервис (Sentry) — сейчас только JSON-логи.
- [ ] Бэкапы БД и план восстановления.

## 5. Возможные улучшения 🚀

### Продукт
- **Загрузка фото/видео осмотра** прямо в кабинете с авто-разметкой повреждений (vision уже есть — довести до UI).
- **Голосовой ввод дефектов** (Whisper уже подключён) в веб-интерфейсе, не только в боте.
- **История цен объявления** в виде графика (данные мониторинга уже собираются).
- **Сравнение нескольких авто** бок о бок (эндпоинт сравнения есть — усилить в UI).
- **Шаблоны переговоров/торга** на основе найденных рисков (логика `negotiation` есть).
- **Реферальная программа** и промокоды для роста.

### Технические
- **CI/CD** (GitHub Actions): прогон тестов + линт + авто-деплой на Railway/Vercel.
- **Кэширование** результатов парсинга и VIN (Redis) для снижения нагрузки и стоимости.
- **Очередь задач** для тяжёлых операций (парсинг, LLM, PDF) — частично есть (`task_queue`), масштабировать.
- **Покрытие тестами** vision/LLM-путей и контрактные тесты на парсеры (ломаются при смене вёрстки сайтов).
- **Наблюдаемость**: дашборды Grafana поверх Prometheus, алерты на падение парсинга и ошибки платежей.
- **Типобезопасность фронта**: миграция Vue-компонентов на TypeScript.
- **Чистка репозитория**: десятки статусных `.md/.txt` и крупные `.png` (≈25 МБ) в корне — вынести в `docs/` или артефакты, чтобы репо был легче.

### Монетизация / рост
- Тариф «разовая проверка» (pay-per-report) помимо подписки.
- B2B-API для автосалонов/перекупщиков (оптовые VIN-проверки).
- Партнёрки с магазинами запчастей и страховыми.

## 6. Приоритетный порядок действий (рекомендация)

1. **Починить тесты** → зелёный `pytest` как точка отсчёта.
2. **Завести боевые ключи** (.env прод) и поднять стейджинг.
3. **Сквозной деплой** Railway + Vercel + домен, проверить регистрацию → проверку авто → PDF.
4. **Платежи и email** в бою.
5. **Стабилизировать парсинг Avito** (прокси/профиль) и Autocode.
6. **Поднять воркер мониторинга** и уведомления.
7. **Определиться с единым фронтендом** и почистить дубли.
8. Юридические страницы + Sentry + бэкапы → **публичный запуск**.
9. Далее — улучшения из раздела 5.

## 7. Главные риски (из самого проекта)

- **Парсинг Avito**: капча/блокировки на новом IP — самая хрупкая точка всей воронки.
- **Autocode**: платный B2B, списывает баланс — нужна экономика и лимиты.
- **Магазины запчастей**: могут блокировать парсинг; цены — ориентир, не оферта.
- **Два параллельных UI**: риск рассинхрона и двойной поддержки.
- **Внешние зависимости** (OpenRouter, ЮKassa, Resend): нужен fallback и обработка простоев.
